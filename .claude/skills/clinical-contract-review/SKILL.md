# 临床研究公司合同分类分级审核流程（乙方视角—服务提供方）

## 一、合同整体分类（公司正式唯一版本）

结合公司对外业务合同 + 对内用工协议全部场景，固定四大合同类别，全公司统一执行：

| 序号 | 合同类型                   | 核心特征                                                             | 典型场景                                                    |
| ---- | -------------------------- | -------------------------------------------------------------------- | ----------------------------------------------------------- |
| 1    | **保密协议（NDA）**        | 无交易金额、无交付履约、无合作执行，仅约束保密义务                   | 合作前置沟通、尽调、专家合作、资料交换、涉密对接            |
| 2    | **框架合作协议（Master）** | 长期合作总规则，无单笔具体金额、无具体交付成果，后续通过SOW/订单执行 | 年度客户框架、长期运维框架、常态化战略合作                  |
| 3    | **正式业务合同**           | 具备明确金额、交付范围、验收标准、付款节点、违约责任                 | 系统许可/开发/运维服务、CRO/SMO/数据管理/统计/医学/项目服务 |
| 4    | **用工类协议**             | 劳动关系/劳务关系确立，不涉及业务交易金额                            | 全职入职、业务兼职推广                                      |

## 二、四大类合同标准审批流程（终版固化）

| 合同类型            | 审批链路                                                                | 核心审核部门   | 流程等级       | 平均耗时 |
| ------------------- | ----------------------------------------------------------------------- | -------------- | -------------- | -------- |
| **保密协议（NDA）** | 起草人 → 法务终审                                                       | 仅法务         | 极简流程       | 1天      |
| **框架合作协议**    | 起草人 → 业务Leader → 法务 → 财务（简审）                               | 业务+法务+财务 | 精简流程       | 1-2天    |
| **正式业务合同**    | 起草人 → 业务Leader → 法务 → 财务                                       | 全部门强制审核 | 标准全流程     | 2-5天    |
| **全职劳动合同**    | 起草人（人事）→ 人事审核 → 法务终审                                     | 仅人事+法务    | 人力标准流程   | 1-2天    |
| **业务类兼职协议**  | 起草人 → 业务Leader（业务条款审核）→ 人事（用工合规）→ 法务（法律终审） | 业务+人事+法务 | 专项三合一流程 | 1-2天    |

> **强制规则**：任何节点提出否决级（🔴）修改，该节点不通过即退回修订，重新提交后需该节点重新审核。

## 四、岗位角色与职责总览（乙方视角）

### 1. 合同起草人（商务/运营/技术/人事）

**核心职责**：

- 完整锁定服务范围SOW，明确我方交付边界，拒绝无限扩展义务
- 整理全部商务谈判约定，确保纸面条款与口头约定一致，**客户承诺落纸**
- 评估客户资质与信用（客户付款能力、历史合作记录、行业口碑）
- 标注所有我方需承担的特殊义务/定制要求，避免模板遗漏我方风险暴露
- 明确增项/变更的额外收费机制，防止免费增项

**输出交付物**：合同初稿 + 谈判纪要 + 客户资质评估 + 特殊义务标注说明

### 2. 业务Leader（业务端最高审核人）

**审核范围**：框架合作协议、正式业务合同、业务类兼职协议

**核心职责**：

- 履约可行性：工期、交付节点是否在公司实际能力范围内，避免过度承诺
- 服务范围边界：客户要求是否超出我方能力/资源，是否存在"无限服务"陷阱
- 增项收费保护：变更管理流程是否保护我方增项收费权利，避免免费变更
- 客户配合义务：客户是否承担必要的配合义务（如数据提供、场地准备、权限开通），否则影响我方交付
- 赔付/责任限制：赔付触发条件是否合理，是否设置赔偿上限保护我方
- 验收标准：验收标准是否客观可量化，避免客户主观拒收
- 人员稳定性：客户是否有权强制更换我方人员？更换条件是否合理？

**技能参考**：[business-leader-review.md](references/business-leader-review.md)

### 4. 公司法务（法律条款总风控—保护乙方）

**审核范围**：所有合同类型

**核心职责**：

- 全文条款逻辑校验，前后表述无矛盾、附件效力优先级明确
- **权责对等保护**：剔除仅约束我方、客户免责的霸王条款；确保客户义务对等
- **责任限制**：设置合理赔偿上限，避免无限连带责任；争取间接损失排除
- **知识产权保护**：保护我方背景IP（现有技术、平台、工具），前景IP争取共享或归我方
- **数据安全责任边界**：明确我方承担的数据安全责任范围，避免过重责任
- **终止保护**：限制客户单方终止权，确保终止时已完成工作费用结算；禁止无理由随时终止
- **争议解决**：争取有利管辖地（我方所在地或中立），仲裁优于诉讼
- 用工类：符合劳动法规定，无违规免责、无效条款

**技能参考**：

- 通用法务审核：[legal-review.md](references/legal-review.md) + [general-risk-checklist.md](references/general-risk-checklist.md)
- NDA专属：[nda-review.md](references/nda-review.md)
- 框架协议：[master-agreement-review.md](references/master-agreement-review.md)

- 兼职协议：[part-time-contract-review.md](references/part-time-contract-review.md)

### 5. 财务部（资金风险专项审核—保护乙方收款）

**审核范围**：框架合作协议、正式业务合同

**核心职责**：

- **收款节点保护**：付款节点必须明确、可量化，验收标准客观，避免客户主观拒付
- **预付款争取**：尽量争取预付款（建议≥30%），降低我方资金压力
- **付款周期**：付款周期≤30天，逾期付款违约金≥日万分之五
- **质保金限制**：质保金比例≤5-10%，质保期≤12个月，避免长期资金占用
- **发票与付款解绑**：开票≠付款触发条件，避免先开票后付款长期拖欠
- **税费明确**：税费由客户承担或明确分担比例
- **争议款项**：争议款项不影响无争议部分付款，避免客户以争议为由拒付全部
- **逾期付款保护**：客户逾期付款时我方有权暂停服务，且不承担违约责任

**技能参考**：[finance-review.md](references/finance-review.md)

## 五、通用审核底线（乙方视角—保护公司利益）

所有合同，无论类型、金额、流程等级，必须同时满足以下底线：

1. **权责对等**：杜绝仅约束我方、客户免责的霸王条款；双方义务必须对等。
2. **金额零歧义**：收款金额、付款节点、计费规则、增项收费零歧义、零模糊。
3. **责任有上限**：我方赔偿必须设置合理上限（通常不超过合同金额），禁止无限连带责任。
4. **收款有保障**：付款节点明确、验收标准客观、逾期付款有违约金、争议不影响无争议部分付款。
5. **终止有保护**：客户单方终止必须提前通知（≥30天）、支付已完成工作费用、禁止无理由随时终止。

违反以上任一条底线，即触发🔴否决级，必须修改后方可进入下一审批节点。

> 注：原"临研合规兜底"底线调整为"责任有上限"，因作为乙方，GCP合规是基本义务，但责任边界需明确；新增"收款有保障"和"终止有保护"两条乙方核心底线。

## 六、合同修改分级标准

| 分级         | 标识 | 定义                                                                                     | 处理要求                                                                           |
| ------------ | ---- | ---------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| **否决级**   | 🔴   | 违反通用审核底线，或存在重大法律/业务/资金风险，可能导致公司重大损失、无限责任、收款风险 | 必须修改，否则不通过，退回该节点重新审核                                           |
| **重要风险** | 🟡   | 存在中等风险，可能导致合同纠纷、利润损失、额外成本、客户过度约束                         | 建议修改，如客户拒绝，法务累计超3项/业务财务累计超2项需升级至部门负责人/管理层决策 |
| **一般优化** | 🟢   | 条款表述可优化、建议补充，但不影响核心风险                                               | 记录备案，可接受客户不修改                                                         |
| **信息提示** | ⚪   | 业务背景说明、条款逻辑提示，供后续执行参考                                               | 无需修改，仅提示                                                                   |

### 升级决策规则

- 🔴 否决级条款：任何审核节点提出即触发否决，必须修改后重新提交该节点审核
- 🟡 重要风险条款：累计超过3项（法务）或2项（业务/财务）需升级至部门负责人/管理层决策
- 🟢 一般优化条款：累计超过5项建议集中沟通，但单独不触发升级

## 九、使用方式

1. **先判定合同类型**：按四大类分类标准判定，加载对应审批链路
2. **按流程等级执行**：极简/精简/标准全流程/人力流程/三合一流程
3. **先过通用审核底线（乙方版）**：任何合同必须先检查5条乙方底线，违反即🔴否决
4. **按岗位加载对应Skills**：各审核人仅加载自己岗位的审核技能文件，乙方视角保护公司利益
5. **分级标注修改建议**：每处修改必须标注🔴🟡🟢，便于升级决策和谈判
6. **版本管理**：每轮修订后标注版本号，修订后的条款需原审核节点重新确认
